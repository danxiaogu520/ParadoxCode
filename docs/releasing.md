# Release process

ParadoxCode has not published a public release. This checklist defines the minimum evidence required
before creating one; it is not a claim that the current alpha satisfies every item.

## Release ownership

Only a project maintainer may create version tags, publish GitHub Releases, or submit/update the Zed
extension registry entry. Release credentials must not be stored in the repository or printed in CI
logs.

## Before a release candidate

- [ ] The changelog describes all user-visible changes and migrations.
- [ ] The version agrees across Cargo packages, `pdx --version`, `pdx-ls --version`, and the Zed
      extension manifest.
- [ ] `cargo fmt`, check, test, clippy, docs, grammar, fuzz-build, dependency-policy, rules, and Zed
      package gates pass from a clean checkout.
- [ ] The embedded first-party rules artifact passes schema, canonical hash, provenance, and
      redistribution checks.
- [ ] Windows and every other advertised target build from CI, and archive contents match the
      documented artifact contract.
- [ ] Every archive has a SHA-256 checksum generated by CI.
- [ ] A clean Windows machine installs the Zed extension, downloads the correct server, validates
      its checksum, starts it, and completes the smoke checklist without a Rust toolchain.
- [ ] No Vanilla files, user caches, native CWT sources, credentials, or local paths are present in
      the source or release artifacts.
- [ ] Known limitations and supported platforms are documented accurately.

## Required smoke test

On a clean EU4 Mod workspace, verify file recognition and highlighting, diagnostics, completion,
hover, definition, references, symbols, formatting, safe rename, overlay updates, dependency
resolution, and explicit Vanilla cache creation/refresh. Inspect Zed logs for crashes or protocol
errors.

## Publication sequence

1. Freeze the release candidate commit and run all release-readiness automation.
2. Review generated archives, checksums, licenses, rules metadata, and the changelog.
3. Create a signed `vMAJOR.MINOR.PATCH` tag from the reviewed commit.
4. Publish immutable GitHub Release artifacts.
5. Update the Zed extension to the exact server version and checksums.
6. Run the clean-machine smoke test against the published artifacts.
7. Publish the Zed extension update and monitor installation failures.

If the post-publication smoke test fails, stop distribution, document the failure, and publish a
new patch version. Do not replace assets under an existing version tag.

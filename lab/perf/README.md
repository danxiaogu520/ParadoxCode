# 性能测量

性能工作流已迁入 Rust [tools](../../crates/tools/README.md#performance-measurements)。
从仓库根目录运行 `cargo run --locked -p tools -- perf --help`。

0.5.1 后的性能修复覆盖规则身份复用、工作区符号查询、补全候选筛选和任务树排版。
补全基准启用生产 Rules IR 并要求实际产生候选。任务树排版基准测量 JavaScript 计算，
真实 GPU 帧率需要在编辑器宿主中另行测量。

冷索引深度优化以上一轮修复后的冻结二进制为基线，对 8,687 个 Vanilla 文件进行三轮
顺序配对：扫描中位数由 16,515 ms 降至 6,150 ms，含缓存写入的总耗时由 19,131 ms
降至 8,760 ms。完整索引内容一致（仅生成时间不同），补全与任务树的 LSP 响应一致。
测量使用全新索引路径，未清空操作系统文件缓存。详细记录、二进制和语料相关证据
保留在忽略的本地输出目录；仓库仅记录汇总结论和自有回归测试。

嵌入脚本参数的补全验证现在只解析被编辑的参数，复用原调用的作用域、兄弟参数
和模板程序，避免每个候选重新解析整个文件并重建语义信息。自有合成样例包含 2,000 个
无关事件，空前缀产生 943 个候选；优化构建的三次 stdio LSP 请求中位数由
7,052 ms 降至 90 ms。LSP 返回的全部 512 项在排序、插入文本和验证证据上逐项一致
（忽略快照修订号）。这是本机合成场景测量，不代表所有工作区的补全耗时。
`quoted_queries` 基准覆盖此场景，同时断言实际候选存在和无关事件不改变候选；
原有的 250 条语句样例也显式提供模板定义，防止空补全结果掩盖性能问题。

补测覆盖了整个 Rust 工作区（1,098 项通过，1 项子进程测试入口按设计忽略）、
16 组 Unicode/emoji、LF/CRLF、四层引号及未闭合输入组合，以及 128 组固定种子的
损坏输入。VS Code 宿主的 8 项测试通过，其中新增 30 次实际编辑后的补全提供器调用。
新旧实现还导出并逐字节核对了截断前全部 943 项候选。参数正文为 250 和 2,000 条
语句的基准独立于外围文件大小基准，避免混淆两种成本。

真实重放选取 EDG 的事件、任务、scripted effect 和 scripted trigger 大文件。
Vanilla 缓存含 8,687 个文件，EDG 含 7,887 个文件，再加一个自有依赖文件，合计
16,575 个文件。每个位置进行 30 次稳定请求和两轮各 30 次、间隔 25 ms 的增量修改，
后一轮同时发起重索引。稳定结果的新旧指纹一致；末次输入的结果与停止输入后的
结果一致，过期重索引的拒绝结果单独保留。

首轮补测发现连续输入的最后一次有效请求耗时约 3.9–27.7 秒，取消响应也长时间等待。
后续修复了两处阻塞：等待解析的补全请求不再挡住后续编辑和取消通知；关闭文件的
磁盘前端不再参与每次编辑的覆盖文档符号事务，查询时仍按当前快照刷新。已经暂存、
尚未解析的连续编辑也不会重复撤销同一组符号。其他检索请求和生命周期消息保持
原有顺序，仍打开的文档继续同步更新符号事实。回归测试覆盖扫描被阻塞时的取消、
关闭文件的分析次数、连续暂存和提交，以及缓存查询在定义覆盖及撤销后的正确性。

相同语料、位置、增量修改和重索引设置下，最终末次输入响应耗时为 171–702 ms，
稳定查询 P95 为 3.3–3.7 ms；五个位置的源文件及稳定候选指纹与基线一致。
这些数值来自本机 stdio 重放。连续输入时大量请求取消，因此不能将其中少数有效
请求的 P95/P99 当作充分采样的尾延迟估计。报告中的 `passed` 表示功能与结果
新鲜度检查通过，延迟需单独查看。仅 EDG 的全文件替换压力测试另存记录，未与
这个增量修改结果混合统计。

另外重放了两个带引号的真实参数位置：`00EDG_RIGMissions.txt` 中的
`rig_every_subject_country_effect.effect`，稳定查询中位数从 83.2 ms 降至 3.0 ms，
候选指纹一致；`01example_ERS_events.txt` 中 Vanilla `for.effect` 内的 `spawn_rebels`
最初返回空候选，被重放工具明确报告为失败。其原因是投影片段中的外层块被误判为
当前标量值的所属属性，现已限制到光标所在的有效容器。回归测试覆盖裸参数、
`hidden_effect`、变量和循环包装下的完整及部分块键。两个真实位置各进行 12 次
稳定查询及连续编辑，最终均返回有效候选；`spawn_rebels` 位置返回 2 项。

`tools perf completion` 保存原始样本、有效/空/取消计数、P50/P95/P99、输入与二进制
指纹和实际源根清单；自有重放已接入 `tools lsp test`。编辑器测试测到命令、中间件
与 LSP 返回为止，尚未测量建议窗口绘制、原生 Windows 或源码行/分支覆盖率。

| 命令 | 职责 |
| --- | --- |
| `perf bench` | 预热、重复基准、原始日志和中位数 |
| `perf baseline / ab` | 冻结二进制、基线和阈值比较 |
| `perf sweep` | 全量语料、查询电池、阶段和进程资源 |
| `perf probe / compare` | 真实 LSP 生命周期、打开/编辑发布、hover 与补全延迟 |
| `perf completion` | 增量输入、取消和重索引并发重放，核对候选和最新编辑结果 |
| `perf memory` | 顺序运行 mem_probe，记录被测子进程峰值、各阶段 RSS 和诊断签名 |
| `perf profile` | 调用 samply 或 Linux perf |
| `perf init / status / import-corpus / control` | 环境检查、语料导入和 native 对照组 |

## 内存配对

`mem_probe` 保留在 engine 示例中：`cargo build --locked --release -p engine --example mem_probe`。
`perf memory --require-identical-diagnostics` 核对每次测量的诊断文件数、数量和 digest。
精确峰值使用 Unix time 的 wait4；LSP 的周期 RSS 是独立的采样指标。缺失采样会显式保留。

机器配置使用忽略的 `target/perf/config.local.toml`，参数优先。环境变量仍可选择本地输入；
原 Shell 配置不再执行。导入的语料留在 `data/`，测量、缓存、画像和对照组构建留在 `target/`。
冷测量创建独立的新缓存，构建时间单列为 `cache_build_ms`，保留已有缓存。

诊断正确性归[语义审计](../audit/README.md)。远端 [Performance 工作流](../../.github/workflows/performance.yml)
只测仓库自有 benchmark。平台依赖、具体命令和统计边界见 tools 指南。
